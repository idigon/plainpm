# plainpm

A markdown-based project management system powered by AI coding agents. No databases, no SaaS — just plain text files, YAML front matter, and natural language commands.

Works with **Claude Code**, **GitHub Copilot**, **Windsurf**, **Cursor**, or any AI agent that reads project instructions.

Works for **individual contributors** tracking their own tasks and for **team leads** managing a group. Meeting transcripts go in, structured notes and tasks come out.

## Why plain text?

- **Portable** — it's just files. Git, Dropbox, USB drive, whatever.
- **Readable without tools** — every task, project, and meeting note is a markdown file you can open anywhere.
- **Diffable** — `git log` shows you exactly what changed and when.
- **AI-native** — any AI coding agent reads and writes these files directly. No API wrappers, no plugins.
- **Agent-agnostic** — switch between agents freely. Your data and conventions stay the same.

## What you get

| Command | What it does |
|---------|-------------|
| today | Daily dashboard — overdue, due today, in-progress, blocked, not started |
| this_week | Weekly dashboard — all projects, streams, and tasks |
| my-team | Team workload with working-days-open per task |
| weekly-report | Week summary — completed, new, blocked, in-progress |
| new-task | Create a task from natural language |
| process-meeting | Turn a `.vtt` transcript or `.md` notes into structured meeting notes + task files |
| status | Project status report (one project or portfolio-wide) |
| done | Mark task(s) as done with one command |
| update | Batch update tasks from natural language |
| agenda | Generate a meeting agenda from open tasks |
| archive | Archive completed tasks older than N days to `data/archive/` |

Dashboards are generated by a Python script (`scripts/dashboard.py`) for speed and determinism. Every run saves a dated snapshot to `data/reports/` so you can track progress over time.

## Supported agents

| Agent | Config file | How to invoke commands |
|-------|------------|----------------------|
| Claude Code | `CLAUDE.md` + `.claude/commands/` | `/today`, `/new-task ...`, etc. |
| GitHub Copilot | `.github/copilot-instructions.md` | "Run today dashboard", "Create a new task..." |
| Windsurf | `.windsurf/rules/plainpm.md` | "Run today dashboard", "Create a new task..." |
| Cursor | `.cursor/rules/plainpm.mdc` | "Run today dashboard", "Create a new task..." |
| Any other | `AGENTS.md` | "Run today dashboard", "Create a new task..." |

All agents read from the same source of truth:
- **`CLAUDE.md`** — conventions (statuses, priorities, IDs, file locations, rules)
- **`prompts/commands/`** — command prompts (one `.md` per command)

## Folder structure

```
plainpm/
├── CLAUDE.md                        # Conventions (single source of truth)
├── AGENTS.md                        # Cross-agent instructions
├── INSTRUCTIONS.md                  # Full usage guide
├── .claude/commands/                # Claude Code slash commands
├── .github/copilot-instructions.md  # GitHub Copilot config
├── .windsurf/rules/                 # Windsurf config
├── .cursor/rules/                   # Cursor config
├── prompts/commands/                # Shared command prompts (all agents)
├── scripts/dashboard.py             # Dashboard generator (Python 3, stdlib only)
├── templates/                       # File templates
├── data/                            # User data (gitignored or submodule)
│   ├── projects/
│   │   ├── _index.md                # Master project list
│   │   └── <project>/
│   │       ├── project.md
│   │       ├── tasks/YYYY/          # Tasks grouped by year
│   │       ├── streams/
│   │       │   └── <stream>/
│   │       │       ├── stream.md
│   │       │       └── tasks/YYYY/
│   │       └── meetings/YYYY/MM/
│   ├── meetings/
│   │   ├── transcripts/YYYY/MM/     # Drop .vtt files here
│   │   ├── notes/YYYY/MM/           # General meeting notes
│   │   └── areas/
│   │       └── <area-slug>/         # One folder per meeting area
│   │           ├── area.md          # Area definition
│   │           └── notes/YYYY/MM/   # Area meeting notes
│   ├── team/                        # One .md per team member
│   ├── archive/                     # Archived completed tasks
│   │   └── <project>/YYYY/
│   └── reports/                     # Auto-saved dashboard snapshots
│       ├── daily/YYYY/MM/
│       ├── weekly/YYYY/MM/
│       ├── team/YYYY/MM/
│       └── weekly-report/YYYY/MM/
```

Tasks are organized into year subfolders. Meetings and reports use year/month subfolders to keep folders manageable at high volume.

The `data/` directory is gitignored by default, so you can share the framework repo without exposing personal data. For private backup, you can point `data/` to a separate private repo via git submodule.

## Quick start

### Prerequisites

- Python 3.10+
- One of: [Claude Code](https://docs.anthropic.com/en/docs/claude-code), VS Code + GitHub Copilot, Windsurf, or Cursor

### Setup

```bash
git clone https://github.com/YOUR_USERNAME/plainpm.git
cd plainpm
```

1. **Add yourself** — create a file in `data/team/` with `self: true` (see `templates/team-member.md`):

    ```yaml
    ---
    type: team-member
    full_name: Your Name
    first_name: YourFirstName
    role: Your Role
    self: true
    ---

    ## Notes

    ```

    This lets you say "assign to me", "I need to...", or "my task" in commands.

2. **Add team members** (optional) — create one `.md` file per person in `data/team/` with `self: false`. Skip this for solo use.

3. **Delete the sample data** — remove `data/team/sample-member.md` and the sample project (they exist as examples).

4. **Open in your agent**:

    | Agent | How |
    |-------|-----|
    | Claude Code | `claude` from the repo root |
    | VS Code + Copilot | Open folder in VS Code |
    | Windsurf | Open folder in Windsurf |
    | Cursor | Open folder in Cursor |

5. **Create your first task**:

    ```
    "I need to set up CI pipeline for project atlas, high priority"
    ```

6. **Check your dashboard**:

    ```
    "Run today dashboard"
    ```

## How tasks work

Every task is a markdown file with YAML front matter:

```yaml
---
id: ATLAS-BE-001
type: task
project: project-atlas
stream: backend-api
owner: Ana
status: todo
priority: high
due_date: 2026-03-15
created: 2026-02-24
completed_date:
tags: [development]
blocked_by: []
links: [{label: "Jira ticket", url: "https://jira.example.com/ATLAS-42"}]
source_meeting:
---

## Set up CI pipeline

Configure GitHub Actions for the backend API service.

### Updates
- 2026-02-24: Created, assigned to Ana
```

Status values: `todo` | `in-progress` | `blocked` | `done`

Priority values: `critical` | `high` | `medium` | `low`

Dependencies: use `blocked_by: [TASK-ID, ...]` to declare that a task depends on others. When a blocker is marked done, the agent notifies you about unblocked downstream tasks.

Task IDs: `PROJECT-STREAM-NNN` for stream tasks, `PROJECT-NNN` for project-level tasks.

## Meeting processing

Drop a `.vtt` transcript (from Zoom, Teams, etc.) into `data/meetings/transcripts/YYYY/MM/` and ask your agent:

```
"Process meeting data/meetings/transcripts/2026/02/2026-02-24-sprint-review.vtt"
```

The agent will:
- Generate thorough, structured meeting notes (summary, decisions, action items, discussion notes)
- Cross-reference attendees with your team roster
- Create task files for every team member action item
- List external attendees' action items in the notes only (no task files)

Meeting notes favor completeness over brevity — nothing gets lost.

## Dashboards

The four dashboard commands run a Python script that parses all task files and generates markdown tables. No AI involved — fast, deterministic, and reliable.

```bash
# Run directly from terminal (no AI agent needed)
python scripts/dashboard.py today
python scripts/dashboard.py this_week
python scripts/dashboard.py my_team
python scripts/dashboard.py weekly_report
```

Every run auto-saves a snapshot to `data/reports/<type>/YYYY/MM/` so you can compare week over week.

## Meeting areas

Meeting areas let you group recurring meetings that aren't tied to a specific project — team syncs, partner engagements, 1:1s, all-hands, vendor calls, etc.

To create a new area:
1. Create a folder under `data/meetings/areas/<area-slug>/`
2. Add an `area.md` definition file (from `templates/area.md`)
3. Drop notes in `data/meetings/areas/<area-slug>/notes/YYYY/MM/`

No project file needed. Tell your agent when processing a meeting: "this is a team sync" or "area: partner-engagements".

See [INSTRUCTIONS.md](INSTRUCTIONS.md#meeting-areas) for full details and examples.

## Customizing

- **Team roster**: add/remove files in `data/team/`
- **Meeting areas**: add folders in `data/meetings/areas/` (each with an `area.md` from `templates/area.md`)
- **Tag taxonomy**: edit the list in `CLAUDE.md`
- **Templates**: modify files in `templates/` to change what new tasks/projects/meetings look like
- **Command prompts**: edit `prompts/commands/*.md` to change how commands behave
- **Dashboard output**: modify `scripts/dashboard.py` to change table formats, sections, or calculations
